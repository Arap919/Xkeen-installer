# XKeen Installer

Графический мастер установки XKeen, Mihomo/Xray, router-watchdog и XKeen UI PWA на подготовленный Keenetic.

## Подготовка роутера

Для новой установки подготовьте EXT4-раздел, установите компоненты OPKG, SSH и SMB в KeeneticOS и разрешите учётной записи доступ к существующему SMB-ресурсу корня раздела. Выберите в мастере новую установку и подключитесь к SSH администратора KeeneticOS (обычно `admin:22`). Мастер определяет точную модель и архитектуру, предлагает подходящие EXT4-разделы, сам скачивает и переносит архив после проверки и вашего подтверждения конкретного плана. При нескольких разделах цель выбираете вы. Другой OPKG-диск, существующее дерево Entware, пользовательский initrc, неоднозначный SMB-ресурс или чужой установочный архив блокируют bootstrap.

План показывает UUID, архив, SHA256 и точные изменения OPKG. На проверенном пустом разделе он явно задаёт временный Initrc `/opt/etc/init.d`, чтобы KeeneticOS запустил `doinstall` из архива. Штатный установщик Entware затем задаёт конечный `/opt/etc/init.d/rc.unslung` и сохраняет настройки; пользовательский initrc блокирует bootstrap. Для уже выбранного того же пустого раздела он включает снятие привязки OPKG и повторное назначение этого UUID. Архив проверяется по закреплённым разработчиком размеру и SHA256, структуре tar и ELF-архитектуре `bin/opkg`; после передачи проверяется обратным чтением. Эти хеши описывают проверенные разработчиком байты официальных HTTPS-архивов, а не опубликованные upstream checksum. При изменении архивов загрузка блокируется до нового просмотра метаданных разработчиком.

После запуска OPKG проверьте в KeeneticOS Initrc `/opt/etc/init.d/rc.unslung` и подключитесь к SSH Entware (обычно `root:222`) с текущими данными. Новый SSH-ключ требует отдельного подтверждения. В текущей bootstrap-сессии мастер также проверяет конечный firmware Initrc и исполняемый `rc.unslung`. Только успешный inspector с `opkg list-installed` позволяет перейти к установке XKeen; переданный архив не означает работоспособный Entware. Для существующего Entware сразу используйте режим существующей установки. Форматирование, установка компонентов KeeneticOS, настройка SMB-доступа, DNS и политики выполняются вручную; мастер не перезагружает роутер.

Последовательность работы: подготовка → подключение → проверка → ядра → компоненты → конфигурация → просмотр и подтверждение плана → установка → проверка результата. Конфликты конфигурации требуют ручного согласования. До записи создаётся проверяемая закрытая резервная копия. Отмена сохраняет выполненные изменения; повтор требует новой проверки и подтверждения нового плана.

Пароли и подписки не сохраняются в browser storage или отчётах. Первый ключ SSH подтверждается отдельно и хранится в памяти до закрытия приложения; неожиданная замена блокируется. Ключ локального CA остаётся в закрытом хранилище компьютера. Установка доверия CA требует отдельного подтверждения; на других устройствах доверие настраивается вручную.

## Сборка

Зафиксированы Wails 2.17.1, Go 1.26.3 и Node.js 26.5.0 с npm. Нужны системные зависимости [Wails v2](https://v2.wails.io/docs/gettingstarted/installation/). WebView берётся из системы:

| Цель | Среда сборки и запуска | Результат |
| --- | --- | --- |
| Windows amd64 | Windows 10/11, установленный WebView2 Runtime | `xkeen-installer.exe` в ZIP |
| macOS amd64/arm64 | macOS 12+, Xcode Command Line Tools для сборки, системный WKWebView | `xkeen-installer.app` в ZIP |
| Linux amd64 | Ubuntu 24.04; GTK 3 и WebKitGTK 4.1, для сборки также gcc/pkg-config и development packages | `xkeen-installer` в tar.gz |

Минимум macOS 12 учитывает [требования Go 1.26](https://go.dev/wiki/MinimumRequirements); работа на старых версиях macOS не проверена. Linux-архив зависит от системных библиотек Ubuntu 24.04 и не является универсальным пакетом для всех дистрибутивов.

Из корня проекта:

```sh
cd frontend
npm ci
npm run typecheck
npm test
npm run build
cd ..
go test ./...
go vet ./...
go run github.com/wailsapp/wails/v2/cmd/wails@v2.17.1 build
```

На Linux установите `build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev`; добавляйте `-tags webkit2_41` к Go test/vet и Wails build. На Windows используйте `build -platform windows/amd64 -webview2 error`: приложение требует установленный WebView2 и не загружает его автоматически. На macOS для минимума 12 задайте `CGO_CFLAGS=-mmacosx-version-min=12.0` и `CGO_LDFLAGS=-mmacosx-version-min=12.0` перед сборкой.

На macOS результат находится в `build/bin/xkeen-installer.app`. Режим разработки: `go run github.com/wailsapp/wails/v2/cmd/wails@v2.17.1 dev`.

## Что проверено

На компьютере: тесты Go, vet, frontend typecheck/тесты/production build и нативная сборка macOS arm64. Сценарии установки проверяются через fixtures, а SSH/SFTP и HTTPS — локальными тестовыми серверами. Команды, соответствие сценариям и ограничения перечислены в [docs/testing.md](docs/testing.md).

GitHub Actions проверяет pull request в `main` и собирает четыре установщика: Windows x64 (`.exe`, NSIS), Linux x64 (`.deb`, Ubuntu 24.04), macOS Intel и Apple Silicon (`.dmg`). Файлы доступны в artifacts запуска.

После мержа в `main` (а также прямого push в `main`) workflow выбирает следующую patch-версию, выполняет тесты и все четыре сборки, затем публикует аннотированный тег и GitHub Release с установщиками и `SHA256SUMS`. Первый выпуск — `v0.1.0`, следующий — `v0.1.1`. Версия в метаданных приложений выставляется при сборке. При ошибке любой сборки релиз не публикуется. Повторный запуск коммита с существующим тегом использует прежнюю версию. Доступен ручной запуск workflow из `main`.

Скачать установщики: [GitHub Releases](https://github.com/Arap919/Xkeen-installer/releases/latest). Для установки Linux-пакета: `sudo apt install ./xkeen-installer-*-linux-amd64.deb`. На macOS откройте DMG и перенесите приложение в Applications. На Windows запустите setup EXE; нужен WebView2 Runtime.

На реальном роутере: установка, сетевые политики, запуск ядер, watchdog, HTTPS/PWA и повтор после обрыва не проверены. Системное доверие CA также не устанавливалось. Fixtures не подтверждают работу пакетов и служб на устройстве.

Установщики выпускаются без подписи сертификатом издателя и без Apple notarization. Wails может выполнять локальную ad hoc подпись macOS. Windows и macOS могут предупреждать о неизвестном издателе; подпись для распространения требует отдельных сертификатов.

Базовый Xray-шаблон создан по пользовательскому Mihomo-конфигу: [маршруты, подключение прокси и отличия](docs/xray-base.md).

Полный пользовательский Mihomo-конфиг встроен в сборку: порты, DNS Fake-IP, группы и правила. На шаге конфигурации можно указать до 10 HTTPS-подписок для каждого выбранного ядра. Mihomo использует провайдеры VPNProvider, VPNProvider1–VPNProvider9; группы Proxy и BENCHMARK используют все заданные провайдеры. В рабочем экземпляре API и benchmark ограничены loopback, создаётся случайный API secret; watchdog использует Proxy/BENCHMARK. Существующие конфигурации не заменяются.

Локальный файл и подписки выбираются по отдельности. Для Xray поддерживаются JSON-объект с outbounds или массив таких объектов: мастер импортирует только прокси-подключения, сохраняя базовые DNS и маршруты, и выбирает первый подходящий узел. URL скрыты в интерфейсе и очищаются при запуске, завершении и закрытии сессии. Для новых управляемых конфигураций Xray подписки обновляются каждые 12 часов; перед заменой выполняются проверка конфигурации и контроль хеша, поэтому ручные изменения не перезаписываются. Cron устанавливается и проверяется автоматически по подтверждённому плану; существующие задания сохраняются, неоднозначная или конфликтующая служба блокирует установку. Геобазы Xray берутся из закреплённого ZIP ядра; пользовательские базы сохраняются.
