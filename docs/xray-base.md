# Базовый Xray-конфиг

Встроенный [JSON](../internal/config/templates/xray.json) создан на основе предоставленного пользователем Mihomo-конфига. Он входит в исполняемый файл через существующий `go:embed` и устанавливается как `/opt/etc/xray/configs/00-installer.json` только при отсутствии существующих конфигураций Xray. Существующие файлы и их права сохраняются.

## Маршруты по умолчанию

| Группа исходного Mihomo | Xray |
|---|---|
| Global, Proxy, BENCHMARK | `blocked-until-configured`: место реального прокси |
| Russia, Steam, Other, локальная сеть | `direct` |
| Ads | `block` |
| AI, Google, GitHub, Microsoft, Apple, Telegram, Discord, YouTube, Media, Social, Speedtest, IP Check, Adult | тот же прокси |

Личные домены, порядок категорий, Telegram IP и UDP-диапазоны Discord перенесены. Последний маршрут — direct, как исходный MATCH,Other. `ruleTag` подписывает категории; для изменения пути категории измените её `outboundTag`. Отключённый MRS adlist не подключён; реклама определяется category-ads-all. Повторное позднее правило category-speedtest пропущено как недостижимое.

## Подключение реального прокси

Для новой установки укажите в мастере до 10 HTTPS-подписок Xray: каждая должна возвращать JSON-объект с outbounds или массив таких объектов. Мастер импортирует только прокси-подключения, сохраняет базовые DNS и маршруты и выбирает первый подходящий узел. Для созданного управляемого конфига закрытый список источников и updater устанавливаются по подтверждённому плану; cron обновляет его каждые 12 часов. Проверка Xray выполняется до атомарной замены, а контроль хеша сохраняет ручные изменения; при ошибке остаётся рабочий файл. Существующие конфигурации автоматически под управление подписок не переводятся.

Можно также заменить объект outbound с тегом blocked-until-configured параметрами своего подключения, сохранив тег и маршруты, и импортировать полный JSON из локального файла. Пока это blackhole-заглушка, установщик не активирует шаблон. Реквизиты храните в локальном файле, а не в чате. Локальный импорт и URL-подписки используются по отдельности.

Правила `geosite:*` и `geoip:*` требуют совместимых `geosite.dat` и `geoip.dat` в каталоге ресурсов Xray. Установщик разворачивает отсутствующие геобазы из закреплённого ZIP Xray после проверки архива; пользовательские базы не заменяются. Перед активацией выполняется штатная проверка `xray run -test`. Автоматическое обновление подписок не обновляет геобазы.

## Отличия от Mihomo

- Группы select преобразованы в статические значения по умолчанию. Mihomo proxy-providers, их заголовки и health-check напрямую в JSON Xray не переносятся. Подписки Xray принимаются только в описанном JSON-формате с outbounds; URI-списки и base64 не поддерживаются.
- DNS слушает TCP/UDP 7874 и использует IPv4 DoH Cloudflare/Google. `https+local` отправляет DNS непосредственно, без respect-rules и прокси. Fake-IP, ARC, store-fake-ip и fake-ip-filter Mihomo не копируются: возвращаются реальные IP. Bootstrap-адреса DoH заданы в hosts.
- HTTP: 7890; SOCKS: 7891 и 1080; benchmark HTTP: 17890. Порт 1080 здесь SOCKS, а не mixed. Как в исходном конфиге, входы слушают IPv4 0.0.0.0 без аутентификации.
- Прозрачный TCP/UDP вход использует 50080 для совместимости с существующей интеграцией XKeen, а не Mihomo redir/tproxy 1182/1181. Перехват DNS и сетевые политики KeeneticOS настраиваются отдельно.
- Sniffing HTTP/TLS/QUIC включён. Не переносится ограничение sniffing по портам, find-process-mode, внешний Mihomo API 9090 и Zashboard; это другие механизмы.
- Прямая DNS-резолюция и direct outbound ограничены IPv4. Это не отключает IPv6 в KeeneticOS или в параметрах реального прокси.

Формат маршрутов: [Project X Routing](https://xtls.github.io/en/config/routing). DNS: [Project X DNS](https://xtls.github.io/en/config/dns).

## Проверка сборки

Шаблон прошёл `xray run -test` на Xray 26.10.31 для macOS ARM64 с геобазами из указанных источников: `Configuration OK`. Тесты установщика и `go vet ./...` прошли, приложение macOS ARM64 пересобрано. Это не проверка перехвата трафика на реальном роутере.
