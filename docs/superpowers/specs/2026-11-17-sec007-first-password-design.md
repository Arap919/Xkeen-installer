# SEC-007 — первый пароль Entware до запуска SSH

Статус: проект для согласования. Пользователь выбрал новый пароль в мастере 17 ноября 2026 года. Реализация ещё не начата.

## Цель и границы

При новой установке Entware стандартные учётные данные не должны давать доступ по SSH ни во время установки, ни после перезапуска или прерывания. Пользователь задаёт отдельный пароль root в приложении до передачи команды OPKG. Учётные данные KeeneticOS и существующего Entware не меняются.

Проверено: opt-ndmsv2 1.0-17 содержит одинаковый root-хеш на ARM64/MIPS/MIPSel, принимающий рекламируемый стандартный пароль. Dropbear 2026.94-4 и bin/install не запрещают такой вход. Это доказательство содержимого пакетов, а не доступности SSH на реальном роутере.

## Рассмотренные варианты

1. Выбран пользователем: новый пароль в мастере, установленный до запуска SSH. Сохраняет привычный парольный вход и текущий переход к SSH Entware.
2. Уникальный SSH-ключ с отключённым парольным входом. Требует хранения и восстановления ключа; не выбран.

## Предлагаемое поведение

- В режиме новой установки мастер до подготовки окончательного плана запрашивает отдельный пароль root и повтор. Пароль не совпадает со стандартным; минимальная длина 16 символов, максимальный размер 1024 байта UTF-8; NUL и переводы строк запрещены. Правила одинаково проверяются в UI и backend. Пароль не поступает в команды shell, argv, журналы, события, результаты, localStorage или постоянные файлы компьютера. В существующем режиме новых полей нет.
- На компьютере вычисляется совместимый с точной Entware libc хеш SHA-512-crypt со случайной солью и ограниченной стоимостью. Реализацию алгоритма и стоимость выбирает разработчик после проверки совместимости и времени на всех трёх архитектурах; собственный новый криптографический алгоритм не создаётся. Изменение алгоритма или ослабление правил требует пересмотра дизайна.
- По SMB передаётся только хеш в отдельном ограниченном по размеру файле, привязанном к одноразовому плану и выбранному тому. Подписанный SMB и контрольное чтение обязательны. SMB не считается шифрованным: хеш позволяет офлайн-подбор при перехвате, поэтому требуется длинный отдельный пароль. Файл не содержит открытого пароля. Чужие, повреждённые, устаревшие файлы и неоднозначное состояние блокируют запуск; автоматического перезаписывания нет.
- Канонический архив и его проверка остаются отдельными от персонального файла. Публикация файла и защита первого запуска завершаются и проверяются до команды OPKG. Права файлов проверяются в пределах возможностей SMB; широкие права не выдаются за защиту конфиденциальности.
- Для новой установки действует постоянная блокировка старта Dropbear до завершения установки пароля. Она покрывает штатный старт, перезапуск службы и rc.unslung после перезагрузки. Проверенные пакеты/скрипты изменяются минимально и воспроизводимо; хеши источников и преобразований фиксируются, итоговые архивы и каталог перепроверяются. Нельзя полагаться только на поздний вызов passwd или предупреждение UI.
- Гейт новой установки работает по положительному подтверждению готовности: отсутствующее, повреждённое или устаревшее состояние означает запрет. Готовность проверяется относительно текущей записи root и конкретных заново созданных host keys, а не только флага done. Отсутствие маркера не может классифицировать установку как существующую. Перед повторным bootstrap или новым проходом пакетов готовность отзывается. Порядок: пакет учётной записи → новый root-хеш → новые host keys → проверенная готовность → запуск SSH. Прерывание или перезапись учётной записи/ключей после готовности снова закрывает старт.
- Перед снятием блокировки bootstrap проверяет формат хеша, атомарно устанавливает его только для root, проверяет результат и удаляет временные копии учётных данных. Ошибка, отмена или пропажа файла оставляет SSH закрытым. Старые общие host keys из архива не используются для доступной SSH-службы: успешная генерация новых ключей обязательна перед открытием.
- После bootstrap приложение очищает поле задания пароля. Для подключения к Entware пользователь снова вводит установленный пароль в обычном поле SSH. Проверка host key сохраняется; подключение не объявляется успешным по факту копирования архива.
- Существующие установки сохраняют пароль, ключи и правила старта. Выбор существующего режима опирается на отдельную предварительную проверку реального Entware, а не на отсутствие fresh-маркера. Этот режим не устанавливает изменённые fresh-пакеты учётных записей/SSH и не заменяет ими действующие init-скрипты; неожиданная зависимость на такой пакет блокируется до записи. Изменения пакетных скриптов не должны создавать для них требование персонального bootstrap-файла.

## Прерывание и восстановление

При прерывании SSH остаётся закрытым до подтверждённой установки нового пароля. Мастер сообщает, что повторное копирование поверх частичного Entware запрещено. Восстановление выполняется через прежний административный доступ KeeneticOS и выбранный накопитель: диагностика состояния и документированное завершение либо удаление только точно установленных файлов после отдельного решения пользователя. Скрытого обхода блокировки, включения стандартного пароля и автоматического удаления частичной установки нет. Точная инструкция проверяется в изолированной среде до закрытия задачи.

## Проверка и завершение

- На ARM64/MIPS/MIPSel: точные пакеты, реальный bootstrap и Dropbear в изолированной среде; новый пароль работает, стандартный и неверный не работают. Отдельно проверяется слушающий сервис, а не только сравнение хешей.
- Прерывания до/после установки пакета учётных записей, до/после записи хеша и перед снятием блокировки; отсутствие/подмена файла; перезапуск init; устаревшая готовность после подмены passwd или host keys; повторный проход пакетов. Стандартный пароль не открывает SSH ни в одном состоянии.
- Негативные тесты валидации backend, привязки к плану/тому, SMB-чтения, атомарной записи, утечек в публичных ошибках; сохранение существующих паролей и конфигурации.
- Повторная проверка SEC-001: воспроизводимость архивов, pins, локальные пакеты и отсутствие сетевого fallback.
- Отдельный специалист по безопасности возвращает находки на доработку; закрытие только после устранения замечаний и успешных проверок. Реальный роутер, публикация релиза и изменение системного доверия не входят в эту работу.
