# XKeen Installer — утверждённый дизайн

Отдельное графическое приложение для Windows, macOS и Linux автоматизирует установку Entware, XKeen, Mihomo/Xray, router-watchdog и XKeen UI PWA на подготовленном Keenetic. Пользователь утвердил дизайн в чате 4 ноября 2026 года.

## Границы

Компоненты KeeneticOS, форматирование и выбор накопителя OPKG, DNS, политики клиентов, необходимые изменения порта управления и выдача RCI-токена остаются действиями пользователя. Приложение проверяет готовность и объясняет недостающие действия. Оно не изменяет эти настройки незаметно. Работа с реальным роутером выполняется только после подтверждения конкретного плана внутри мастера; разработка не включает установку на текущем роутере пользователя.

Новый проект: `/Users/olegfirskov/xkeen-installer`. Исходные проекты UI и watchdog не меняются. Интерфейс, README и планы — на русском; исходники, комментарии и технические спецификации — на английском.

## Технологии и рассмотренные подходы

Утверждён графический мастер на Go вместо консольного. Предлагаемый технический стек: Wails, Go, TypeScript. Системные зависимости WebView учитываются в пакетах и инструкции; переносимость Go не означает возможность собрать GUI для всех ОС одной командой на macOS. Первый поддерживаемый набор: Windows amd64, macOS amd64/arm64, Linux amd64; расширение набора требует подтверждённых сборок.

## Мастер

1. Подготовка KeeneticOS и накопителя.
2. Адрес роутера, SSH/SMB-параметры и необходимые учётные данные.
3. Проверка архитектуры, места, Entware, версий и конфигураций.
4. Выбор Mihomo, Xray или обоих; при двух ядрах — активного. Краткое сравнение YAML/Clash и JSON/Xray. Watchdog предназначен для Mihomo.
5. Выбор UI PWA и watchdog, предложенных к установке.
6. Встроенные согласованные шаблоны для новой установки, импорт локального файла или подписки; сохранение существующей конфигурации и просмотр необходимых дополнений.
7. План с версиями, резервной копией и точными изменениями.
8. Выполнение с прогрессом, отменой и повтором после перепроверки состояния.
9. Фактическое состояние служб, адрес панели, резервная копия и ручные действия.

## Entware

Предпочтителен штатный архив для архитектуры ARM64/MIPSel/MIPS и механизм `/opt/install` Keenetic. Передача до появления Entware должна быть проверена: кандидат — SMB на уже настроенный пользователем общий ресурс. Изменение настроек KeeneticOS и автоматическая перезагрузка не входят в разрешённую подготовку. Если для развёртывания нужен повторный выбор накопителя или его переподключение, мастер сообщает об этом и ждёт. При недоступности автоматической передачи пользователь копирует архив вручную, затем мастер повторяет проверку. Нельзя выдавать копирование архива за завершённую установку Entware.

## Существующие установки

Перед первой записью сохранить конфигурации, права, init-скрипты, сертификаты и версии в закрытую резервную копию на роутере; при нехватке места остановиться. Не заменять пользовательские конфиги шаблонами. Патчи показывать без раскрытия секретов; не выполнять неоднозначное слияние YAML/JSON. Проверить конфигурации до активации. Сохранить активное ядро, если пользователь не выбрал переключение. Повторный запуск проверяет реальные файлы и пакеты. Отмена не является полным откатом; журнал показывает завершённые и незавершённые изменения.

## Компоненты

XKeen устанавливается из jameszeroX/XKeen; Mihomo и Xray выбираются независимо. Адаптер установки должен опираться на проверенный неинтерактивный интерфейс upstream, а не посылать слепую последовательность ответов меню.

Watchdog устанавливается штатным IPK из Arap919/router-watchdog с зависимостями Python/PyYAML, HTTPS и cron. Для Mihomo необходимы совместимые select-группа с provider-backed нодами, BENCHMARK, HTTP listener и API secret. Конфигурация watchdog согласуется с ними. При активном Xray служба watchdog не должна переключать ноды неактивного Mihomo. Существующие cron-скрипты обнаруживаются; не предполагается единственное имя S10cron.

UI — релизы Arap919/xkeen-ui-pwa-fork. Существующий setup.sh содержит интерактивное удаление при переустановке; этот путь не используется без разбора. По умолчанию панель на HTTPS-порту 1000, после проверки конфликтов. Сохраняются её существующие данные и настройки.

## HTTPS и секреты

Создать локальный CA и серверный сертификат с SAN адреса роутера. CA key остаётся на компьютере с закрытыми правами; на роутер передаются только серверные сертификат и ключ. Существующий корректный TLS сохраняется. Доверие CA — отдельное явное системное действие, на других устройствах — ручная установка. SSH host key проверяется с подтверждением первого подключения и блокировкой неожиданной замены. Пароли, токены, URL подписок и конфиги не попадают в журналы, Git и frontend localStorage.

## Критерии готовности

Проверены чистая установка и повторный запуск, сохранение существующих конфигураций, оба ядра и выбор активного, watchdog, HTTPS UI, ошибки сети/места/конфига и отмена. Модульные тесты не заменяют проверку на роутере. Реальная установка требует отдельного разрешения пользователя. Публикация, push, подпись приложений и работа с внешними аккаунтами не выполняются автоматически.
