## Исправление эха интерактивной команды

SSH RunCLI возвращает эхо команды перед телом ответа. Исходная CIFS fixture содержала только поля ответа; строгий парсер отвергал начальное show cifs. Новый регрессионный тест воспроизводит этот отказ. Парсер теперь допускает ровно одно известное начальное эхо, не игнорируя произвольные строки. Ошибки выполнения и разбора show cifs разделены.

Проверка echo-fix: регрессионный RED подтверждён, затем go test -race . ./internal/bootstrap ./internal/router прошёл; статическое ревью без блокеров, Wails macOS ARM64 сборка прошла. Отдельные повторные frontend-тесты и новый SSH→Inspect интеграционный тест не запущены: разрешения на эти команды отклонены. Сборка включает прежние Mihomo/Xray. Физический роутер не изменялся.

## Пагинация терминала и причина отказа парсера

Новый воспроизводимый сбой в полном SSH→Inspect сценарии: транспорт отвечает на --More--, но сохраняет маркер в теле ответа. Строгий CIFS-парсер отвергает эту строку. При PTY в 24 строки пользовательский ответ с тремя ресурсами может быть постраничным. RED воспроизвёл тот же parse cifs через реальный loopback SSH. Исправление удаляет по сохранённым позициям только реально обработанные терминальные маркеры, не меняя буквальный текст --More-- в значениях полей. Дополнительно CIFSParseError передаёт только фиксированный тип отказа, номер строки и известное имя поля; значения и неизвестный текст не выдаются.

Проверка pager-fix: RED реального loopback SSH→Inspect воспроизвёл parse cifs из-за --More--; GREEN go test -race . ./internal/bootstrap ./internal/router прошёл, включая paged CIFS, сохранение буквального маркера и закрытые диагностические поля. Независимое ревью без блокеров. Повтор frontend Vitest не запущен: разрешение отклонено. Wails macOS ARM64/typecheck/production build прошёл. Физический роутер не изменялся.

## Подтверждённый CSI-префикс non-PTY ответа

Пользователь выполнил ssh -n -T ... show cifs | LC_ALL=C sed -n '1,6l'. Первая строка — ESC[K (очистка строки), затем enabled: yes и остальные поля. Предыдущий exec-путь передавал этот код как TEXT/1. Новый регрессионный тест полного SSH exec→Inspect воспроизвёл именно parse cifs на фрагментированном ESC[K. Полные CSI-последовательности удаляются существующим cliANSI после сбора ограниченного ответа, до проверок пустоты/CLI-ошибки и разбора. Печатная последовательность \033[K в значении не меняется; ответ из одних CSI и скрытая форматированием CLI-ошибка отвергаются.

CSI-проверка: регрессионный RED полного SSH exec→Inspect и CSI-only/CSI-hidden-error подтверждён. После исправления go test -race ./internal/router -run TestCLI -count=1 прошёл, включая реальный exec с фрагментированным ESC[K и сохранение печатного escape-обозначения. Независимое статическое ревью без замечаний. Wails macOS ARM64/typecheck/production build прошёл. На физическом роутере установка не выполнялась; требуется повторная проверка пользователя.
