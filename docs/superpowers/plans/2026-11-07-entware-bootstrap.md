# Автоматическая установка Entware

> **For agentic workers:** use superpowers:subagent-driven-development. Preserve existing uncommitted first/second-step fixes.

**Цель:** пользователь готовит EXT4-раздел; мастер определяет архитектуру, скачивает и переносит архив Entware и запускает штатный механизм OPKG. Пользователю не нужно выбирать архитектуру, искать архив или копировать его вручную. Путь `/opt/etc/init.d/rc.unslung` остаётся проверкой в KeeneticOS.

**Границы:** необходимые компоненты KeeneticOS и доступ администратора — предварительные условия. Форматирование, смена настроек DNS/политик, установка системных компонентов, включение новых сетевых служб, reboot и реальная установка на устройстве при разработке не разрешены. Существующий Entware сохраняется. При нескольких EXT4-разделах пользователь выбирает цель в мастере; неоднозначный раздел не выбирается автоматически.

**Архитектура:** отдельный клиент firmware SSH (обычно admin:22) выполняет фиксированные CLI-команды для модели, разделов и текущих настроек OPKG/SMB. По точному аппаратному ID выбирается проверенная архитектура; строка `mips` сама по себе endian не определяет. Существующий корневой SMB-ресурс сопоставляется с UUID выбранного раздела. Архив переносится с проверкой readback; затем подтверждённый план запускает обработку через `opkg disk`. Пользовательский initrc блокирует установку и не перезаписывается. На проверенном пустом разделе подтверждённый план временно задаёт `opkg initrc /opt/etc/init.d` для запуска архивного `doinstall`; штатный установщик Entware затем задаёт конечный `/opt/etc/init.d/rc.unslung`. Переход к XKeen в текущей bootstrap-сессии требует также проверки конечного Initrc и исполняемого файла. Текущее подключение к shell Entware (обычно root:222) остаётся отдельным: готовность подтверждается только настоящим inspector и `opkg list-installed`.

**Целостность:** официальные архивы не имеют установленного опубликованного checksum. Можно закрепить проверенные разработчиком точные SHA256 и размер полученных по HTTPS байтов, явно обозначив происхождение; нельзя выдавать эти значения за upstream checksum. Файл передаётся только после проверки архива и его ELF-архитектуры, затем читается обратно и сравнивается до запуска OPKG.

## Проверяемые результаты

Новая установка: hardware ID → MIPS/MIPSel/ARM64 → однозначный EXT4 UUID → проверенный архив → atomic transfer/readback → подтверждённый firmware trigger → ожидание проверки Entware SSH. Существующий Entware не заменяется. Два диска, неизвестная модель, share подкаталога, иной OPKG-диск, custom init, чужой архив, недостаток места, подмена UUID, ошибка чтения/сети, cancellation и повтор не дают ложного installed-success.
